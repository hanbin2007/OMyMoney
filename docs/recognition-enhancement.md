# 可选识别增强契约

当前只提供 `NoOpRecognitionEnhancer`，返回 `Unavailable`。增强接口没有调用模型、下载权重、配置密钥或联网，也不显示 AI 开关；现有无障碍与本地 OCR 流程不依赖增强接口。0.2 的诊断上传和 APK 更新是独立的联网功能，不是 AI 增强。

`EnhancementRequest` 只包含账单标识、版本、少量已有字段、允许的账户/分类 ID、超时和字段证据。它复制并只读封装候选集和证据，限制文本、数量与时间范围，并过滤订单编号、移除附件/标签/完整页面，脱敏长数字。调用者负责传入当前账本和交易类型实际允许的候选 ID；接口不查询数据库。协程上下文提供取消信号。

提供方只能返回字段建议、原文片段及证据索引。`EnhancementValidator` 拒绝非法响应、错误类型、未知候选、重复字段、缺失/不匹配证据，以及迟到版本或其他草稿的结果。账户/分类还与当前候选集再次取交集，防止请求期间已归档的对象重新进入草稿。建议只能返回新草稿副本，不保存或发起付款。

当前可建议金额、支出/收入/转账账户、收入/支出分类和原文备注。金额建议只能确认规则已经确定且全部金额证据一致的正金额，不能从缺失或冲突证据中选择一个金额；不允许改变方向、交易时间、费用、关联账单或完成状态。账户和分类的原文依据不等于语义正确保证，后续仍须人工确认和正式账务验证。备注必须逐字来源于脱敏的商户或备注证据。

调用方必须在每次编辑时递增版本、保留手改字段集合，并在读取最新状态及应用返回结果之间保持串行。验证同时比较对应字段，手改字段即使恢复原值也不得被覆盖。超时、失败或缺少提供方返回最新规则/用户草稿，不返回过期的请求副本；外部取消继续传播。时限依赖协程的协作式取消，未来提供方必须正确释放自身资源，不得使用不可取消的长时间阻塞操作。

纯 JVM `RecognitionEnhancerTest` 使用 fake 覆盖缺少提供方、合法建议、非法 ID/类型/JSON、原文矛盾、重复字段、版本/身份/手改冲突、超时、取消和数据最小化。它不是任何实际模型的准确率或性能证明。
