# 本地识别草稿确认

## 状态与写账边界

- 无障碍采集仅产生持久队列项，不调用保存。只有用户在共享账单表单中点击保存，`RecognitionQueue.resolve(Save)` 才以原始提交 ID 调用事务账务保存。
- 浮层、主应用和稍后重新打开的编辑器使用同一份 `recognition/<id>` 原始输入草稿。输入中的 `12.` 不被格式化成别的值；返回和服务销毁保留草稿，编辑状态回到待确认。
- 忽略是可逆状态，不删除原始识别依据或用户输入；队列的已处理页可重新打开。保存回执原子落库，重复保存不会重复扣款。
- 默认相似记录需要勾选新账单确认。忽略提示仅隐藏自动浮层提示，跳过相似比较仅影响展示；二者都不绕过硬去重、提交幂等和人工保存。
- 比较读取已保存条目对应的最新账单并持续观察其修改/删除，不以入队快照冒充当前账单。差异按展示数据重新计算，显示类型和秒级交易时间；不可用记录不声称字段相同。原始识别依据单独保留。

## 浮层和权限

- 服务托管 `TYPE_ACCESSIBILITY_OVERLAY`，不额外索取普通悬浮窗权限。初始横条仅显示待办数量，`FLAG_NOT_FOCUSABLE` 不抢键盘；用户主动展开才获取焦点。
- 完整表单复用主应用 Material 3 编辑器，拥有独立 lifecycle、saved-state、view-model 和 back dispatcher。账户与日期选择内嵌同一安全窗口，避免服务上下文中的 Activity 对话框令牌问题。
- `FLAG_SECURE` 始终保留。锁屏、暂停、主应用显示、解绑和销毁都移除窗口并释放 Compose composition 和所有者；后续事件不替换当前已展开的草稿。
- 附件选择通过用户明确点击进入主应用后进行，不在后台强启 Activity。窗口拒绝只显示错误并保留队列，主应用设置的识别记录入口不依赖服务授权。
- 通知只显示数量与真实采集状态，不含金额、商户或备注。Android 13+ 首次明确点击才申请通知权限，后续请求转系统通知设置；已关闭的渠道有渠道设置入口。恢复前台后回读权限、应用通知开关和渠道重要性。
- 通知点击打开固定队列路由；暂停/恢复使用显式不可变 PendingIntent 和未导出的接收器。外部 Intent 不能注入或保存账单。

通知渠道入口遵循 [Android 通知渠道文档](https://developer.android.com/develop/ui/compose/notifications/channels)，权限请求遵循 [Android 通知权限文档](https://developer.android.com/develop/ui/views/notifications/notification-permission)。

## 验证证据

- `OverlayReviewTest`：只在显式保存时改余额、连续保存一次、返回保留不完整金额、忽略可恢复、窗口拒绝仍有队列、通知未授权不发布、秒级比较。
- `QueueReviewUiTest`：主应用相似商户比较、勾选门槛、修改返回重开保存；旧账单后改为收入并改变金额、时间差 30 秒、比较页面打开期间删除的实时反馈。
- `NotificationAccessTest`：首次申请、已拒绝/已授予转系统设置以及旧系统入口选择。
- `AccessibilityOverlayDeviceTest` 在专用 API 34 模拟器实际授权服务，检查窗口标志、初始不抢焦点、手动展开、真实输入法、内嵌账户/日期、连续入队不覆盖输入、锁屏撤窗、解锁重开保存、第一次 Back 隐藏输入法、第二次 Back 保留待办并撤窗。硬件 Back 和左侧边缘手势分别执行。
- 合成样本的 360dp 与 600dp、深浅色、200% 字体已检查；安全浮层图通过测试进程绘制自己的视图获得，未关闭安全标志。原生窗口和输入行为由系统 UI 自动化另外断言，软件绘图不充当硬件截图证明。
- 独立 UX 审查的三项重要问题分别有失败后通过的回归。一个轻微问题暂缓：内嵌时间的格式错误与夏令时空缺共用错误文案，不影响拒绝非法时间。

上述不是第三方支付 App 真机兼容证明。厂商后台保活、API 26/36 设备、TalkBack、硬件键盘和系统通知渠道被关闭后的完整人工操作仍未实测。
