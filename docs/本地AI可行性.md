# 钱迹本地复刻的端侧 AI 可行性

当前产品决定：用户已明确本期不部署本地 AI，只预留接口。本文保留作未来技术选型参考，不是当前实施任务。

**结论：可以把这两个云端 AI 环节替换成端侧模型，不必直接删除 AI 功能。** 已核实有支持 Android 的开源推理引擎和小模型；但这只能证明部署路径存在，不能证明目标手机上的速度、耗电或账单准确率已经达标。目标手机型号、内存和 Android 版本尚未提供，尚未运行真机模型测试。

## 不接任何大模型会损失什么

| 功能 | 原 APK 中的分工 | 只保留规则和 OCR 的结果 |
| --- | --- | --- |
| 支付页面金额和时间识别 | 页面规则及字段提取器 | 已适配页面仍可保留，不因取消云 AI 整体失效 |
| 自动分类和子分类 | 无障碍 AI 从已有分类候选中选择 | 语义分类能力缺失，需要手选或补本地分类器 |
| 模糊账户选择 | 本地匹配链加可选 AI | 精确名称和尾号匹配仍在，复杂描述的选择能力可能下降 |
| 整理账单备注 | 可选 AI 返回备注 | 规则仍可提取部分备注，但不等价于语义整理 |
| 任意分享截图生成草稿 | 本地 OCR 后由云端 AI 提取金额、时间、类型、分类和账户 | OCR 仍能读字，但缺少通用文字到结构化账单的环节 |

以上是调用点与实际消费结果的分析，不是仅根据 DTO 字段猜测。无障碍 AI 分支目前主要实际采用分类、账户、备注；截图分支承担更完整的账单结构化任务。原版无障碍 AI 也不是所有未知页面的通用识别器，它在页面规则命中之后才进入填充流程。

## 建议的实现

```text
无障碍节点或用户分享截图
    -> 节点整理或离线中文 OCR
    -> 确定性规则抽取可信字段
    -> 仅对缺失或模糊字段调用本地模型
    -> 限制为固定 JSON，分类和账户只能选已有候选
    -> 用原文、金额规则、日期规则和候选 ID 校验
    -> 生成草稿，用户确认后入账
```

这是一项工程设计建议，不是已经实现并通过测试的流程。金额与交易时间需要能追溯到原文，不允许模型凭空补出付款成功。失败、待支付、退款中等状态应单独处理。模型输出格式正确并不等于业务事实正确；其自报的 confidence 也不能直接当准确率。

优先走“本地 OCR + 文本模型”，而不是每笔交易都把整张图片交给多模态大模型。前者保留可核查文字，减少输入和推理负担，也更接近此 APK 的截图处理路径。ML Kit 官方提供可直接随应用打包的中文识别模型，不必依赖首次动态下载才能读字。[ML Kit Android 文档](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)

## 可验证的候选路线

| 路线 | 已验证的公开基础 | 本项目建议 |
| --- | --- | --- |
| Qwen3.5 2B 量化模型加 MNN | Qwen 发布了 2B 权重；MNN 官方声明支持 Qwen3.5，并有 Android 本地 LLM 应用 | 作为第一组中文账单抽取候选；实际内存和质量须测试 |
| Gemma 4 E2B 移动量化版本加 LiteRT-LM | Google 提供端侧模型与移动量化方案；LiteRT-LM 有 Android Kotlin API | 作为内存和延迟对照候选，不预设中文账单准确率更高 |
| Gemini Nano 加 ML Kit Prompt API | 提供系统端侧提示接口，但依赖 AICore 和设备支持状态 | 不作为未知 Android 手机的唯一方案 |

来源：[Qwen3.5 2B 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-2B)、[MNN 官方仓库](https://github.com/alibaba/MNN)、[Gemma 4 模型说明](https://ai.google.dev/gemma/docs/core)、[移动量化说明](https://blog.google/innovation-and-ai/technology/developers-tools/quantization-aware-training-gemma-4/)、[LiteRT-LM Android](https://developers.google.com/edge/litert-lm/android)、[Gemini Nano 初始化与兼容要求](https://developers.google.com/ml-kit/genai/prompt/android/get-started)。

Qwen 的 2B 参数版本官方定位包括原型和任务专用微调，因此不能把通用榜单分数当作账单生产质量。4B 可以作为较高内存设备的第二档候选，0.8B 可用于小范围分类实验，但目前没有本任务数据证明这些档位的实际优劣。[Qwen3.5 2B](https://huggingface.co/Qwen/Qwen3.5-2B)、[Qwen3.5 4B](https://huggingface.co/Qwen/Qwen3.5-4B)

## 成本和限制

- 模型通常需要独立下载或导入，不能保持原 APK 约 31 MB 的总体积；模型文件大小、运行时工作内存、整机内存是三种不同指标。
- 模型加载和推理放在工作线程，不能阻塞无障碍事件或主界面。LiteRT-LM 官方也明确指出初始化可能耗时较长。[初始化说明](https://developers.google.com/edge/litert-lm/android)
- 无障碍监听持续运行不代表模型应常驻大内存。采用按需加载、短上下文、紧凑输出、重复请求缓存，以及超时退回人工草稿。
- 安装模型后的账单推理可以完全离线。实现仍需审计依赖、遥测、备份和系统设置，不能单凭“本地模型”四字保证所有数据永不离机。
- 未经脱敏的真实账单不用于外部训练或上传。个性化优先存储用户纠正的商户到分类映射，不等同于直接在手机上训练大模型。

## 最小验证

使用同一组脱敏的付款、转账、退款、未付款、优惠后实付和同金额不同商户样本，比较规则基线与候选模型。记录金额完全匹配、时间和收支类型、分类、账户命中、拒绝错误入账、冷启动和热启动延迟、峰值内存、连续处理后的发热及系统回收情况。先验证候选，再决定是否纳入完整 App。

当前状态是“部署路线可行，任务质量与目标手机表现未实测”，不是“已经达到原版 AI 水平”。
