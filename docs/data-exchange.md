# 本地数据交换

## 格式与证据边界

| 格式 | 本地实现 | 验证边界 |
| --- | --- | --- |
| OMyMoney CSV | UTF-8、BOM、RFC 4180 引号与换行；完整精度文本 | Android 实际导出后回读与入账测试 |
| OMyMoney XLSX | 单工作表；金额和文本全部为字符串单元格 | fastexcel 真正生成和读取，不是改扩展名；Android API 34 已运行，其他 API 属于最终验收 |
| OMyMoney JSON | `ExchangeTable` 对象，含 `columns` 和带逻辑行号的 `rows` | 与表格格式相同的字段和精度；不是原版 JSON 格式 |
| 自定义 CSV/XLSX 表格 | 列、账户、分类和币种映射；逐行预览 | 必须能够提供确定的类型、金额、币种、时间及账户；不猜未知值 |
| 钱迹 CSV/XLSX | 静态确认 19 列导出契约；基本支出、收入、转账、信用卡还款映射 | 只通过独立构造的样本，未取得真实导出文件，不宣称完整兼容 |
| 钱迹 JSON | 静态发现 `key/date/category/type/money/currency/asset/from/target/remark` 等字段 | 数字账户/分类 ID 依赖原版目录，暂不作为 OMyMoney JSON 接受 |
| 支付宝、微信及其他原版导入平台 | 原 APK 从 `import/platforms` 取得清单，上传服务器解析 | 静态仅确认支付宝 66、微信 102；未连接服务器，未取得完整清单或真实文件，不宣称兼容 |
| XLS、加密文件、多个工作表 | 不接受 | 不把缺失数据悄悄视为成功 |

原版静态参考为 `work/qianji-java/sources/com/mutangtech/qianji/data/model/Bill.java` 的 `getCsvTitle` / `toExportRow` 与 `network/api/dataimport/a.java`。只读取互操作字段契约，没有复制原版实现。

钱迹模型样本在 `data/src/androidTest/assets/exchange/qianji-modeled.csv`。原版导出的账户1也承载普通收入的入账账户，本地映射按已确认的基本类型决定方向；分类保留两级路径，标签使用原版 `#` 分隔契约，`nc` / `nb` / `nc&nb` 及对应中文标记映射到排除标志。未知币种仍须明确映射。优惠券、已报销汇总、图片及未经样本覆盖的高级类型不会被静默丢弃或猜为普通支出，相关行保持错误状态。钱迹的跨币种 CSV 不包含完整实际换汇快照，不能从名义金额重建另一账户金额。

CSV 使用 [Apache Commons CSV 1.14.1](https://commons.apache.org/proper/commons-csv/download_csv.cgi)。XLSX 使用 [fastexcel 0.20.2](https://github.com/dhatim/fastexcel/releases/tag/0.20.2)，XML 使用其 Aalto 解析器，ZIP 使用 Apache Commons Compress。依赖及传递依赖由 Gradle SHA-256 校验清单固定。实际 Android 测试发现平台 `ZipInputStream` 不接受该写入器的 ZIP64 数据描述符，已使用 Commons Compress 读取，而不是修改工作簿字节或放弃校验。

## 字段

OMyMoney 表格第一列为 `format`，每行为 `OMyMoney-1`。其余列依次为：

`source_id`, `occurred_at`, `zone`, `kind`, `amount`, `currency`, `scale`, `from_account`, `to_account`, `category`, `note`, `tags`, `fee`, `exclude_stats`, `exclude_budget`, `linked_source_id`, `exchange_account`, `exchange_currency`, `exchange_scale`, `exchange_amount`, `exchange_rate`, `exchange_date`。

- 类型使用本地 `BillKind` 名称；金额为十进制文本，禁止浮点中转、超精度截断和溢出。
- 币种是明确 ISO 代码，或用户明确选择的映射；不能将未知代码视为人民币。`scale` 保留本地已有精度约定。
- 时间接受 ISO Instant/带偏移时间，或严格的 `yyyy-MM-dd HH:mm:ss` 本地时间。后者使用所选账本/行内时区；夏令时不存在或重叠的时间必须提供偏移，不猜测。
- 账户按明确映射或唯一的现有名称解析。分类按交易类型及完整 `父分类 / 子分类` 路径匹配，不自动创建或静默丢弃分类。
- `tags` 为 JSON 字符串数组。空字段不同于猜出的默认账户；可选字段留空有明确定义。
- 关联交易使用源 ID，导入时重映射到同一目标账本；选择不完整的关联组会在统一账务校验中拒绝整批。
- 手续费使用实际扣费账户币种。换汇的实际金额、币种、精度、汇率与日期共同保留；不得仅靠当前汇率重算历史。
- 表格交换不是完整备份：不包括图片文件、目录创建、余额期初、草稿、周期计划、存钱计划或设备隐私设置。完整迁移应使用 ZIP 备份。

## 提交与恢复

设置的“账单导入与导出”作用于当前账本；账单列表的导出入口携带当前已应用筛选。导出页面明确显示账本、筛选范围和匹配数，最终内容以导出开始时的数据库快照为准。CSV、XLSX、JSON 均使用系统文件选择器，不申请全盘文件权限。

预览默认不选中任何行。独立复选框有行号、交易类型和金额名称；行详情保留映射后的账户方向、交易时间与时区、分类、手续费和换汇快照，并另列原始字段。映射改变后重新校验并清空选择，不能沿用旧选择直接确认。

解析及映射只生成私有预览，默认不入账。预览在 `noBackupFilesDir/import-previews` 保存 24 小时，并校验内容摘要；未确认预览不进入业务备份。提交使用用户所见的已解析交易和映射，重新检查当前目录、关联关系及最终余额，不在确认后自动改选同名账户。

同一目标账本、文件 SHA-256、逻辑行号产生稳定回执 ID。成功的每行与回执在同一 Room 事务中写入。重开预览、重复确认、重复文件和已删除的历史导入不会再次扣款。OMyMoney 源 ID 另用于跨导出文件去重，已有记录不会被覆盖；修改原文件不是更新历史账单的方法。

错误行和重复行明确区分。选择包含错误行时整批拒绝；仅选择有效行时，只提交明确选中的行。账户状态变化、关联约束、余额溢出、SQLite 写入失败均回滚所有所选行与回执。

提交事务成功后，若暂存预览过期或刷新失败，界面保留已导入数量并明确提示入账成功，不把后续读取错误说成写入失败。重新选择文件仍使用已持久化的回执去重。

Room 10 / ZIP schema 8 增加 `import_receipts` 和 `batch_actions`。每个回执保存原始列标题、原始字段文本、逻辑行号、原文件摘要及时间；保存的是字段内容，不承诺逐字节重建原 CSV 的引号/行尾或 XLSX 容器。完整备份验证这些引用、投影和 ID，合并有冲突时不覆盖；替换恢复同时恢复去重回执与撤销记录。

## 批量操作

批量修改覆盖备注、标签、分类和统计/预算排除标记。金额、币种、账户及交易类型仍通过单笔编辑明确调整。修改与删除都检查选择时的版本；取消不产生写入。

批量删除先确认数量与影响。不能留下未选中的关联子账单；同组选中的来源和结算可以一起删除。所有金额变化一次按精确净额计算，不因逐条处理的中间溢出拒绝合法最终余额。

撤销有效期为 24 小时，保存到本地数据库并进入完整备份。只有全部成员仍处于操作后的版本时才能整体撤销；任何成员发生后续编辑、单笔撤销或删除，都不会被批量撤销覆盖。历史附件引用同样保留到备份中。

历史显示成员摘要与操作短编号，点击可查看操作前的成员记录；撤销控件同时提供操作身份。批量编辑的原始输入和选中版本在页面重建后保留，陈旧版本导致整批拒绝，不以当前版本悄悄覆盖其他修改。

## 设备验证

API 34 的实际 Android DocumentsUI 已分别创建并重新打开 CSV、XLSX、JSON，向新账本导入两条记录，并核对金额、账户、分类和备注。文件位于本地测试证据目录 `work/qa/c9/system-documents/OMyMoney-QA-613b720e.*`，不是使用文件提供器模拟结果替代系统选择器验收。解析边界、原始数据、去重与数据库失败回滚另由仪器测试验证。其他 API、真实第三方导出文件和物理设备不因此视为已通过。

## 安全与限制

- 16 MiB 输入文件、32 MiB XLSX 解压内容、256 个 ZIP 条目、10,000 数据行、64 列、每字段 32,768 字符。超限文件失败，超长可定位的行标记错误。
- 损坏容器或无法确定行边界的 CSV 属于文件级错误，不虚构“其余所有行已检查”。
- XML 禁止 DTD、外部实体、外部链接，并限制嵌套与坐标。公式单元格不能导入，公式从不计算。
- XLSX 导出始终写字符串；CSV 对以公式字符、控制空白或单引号开头的文本加一个单引号保护。只有带 OMyMoney 版本标记的文件才去除该保护层，外来文本的单引号不擅自删除。
- 外部导出文件包含敏感财务信息且没有应用内加密。取消或 I/O 错误可能使用户所选文件只写入部分内容；只有成功返回才报告导出完成。
