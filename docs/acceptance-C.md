# OMyMoney 整体验收报告

## 交付状态

已完成经确认的独立、本地 Android 记账范围。功能回归、原生流程验收与最终签名 APK 在三个系统的实际安装走查均已通过；以下未核实边界和六项小问题仍明确保留。

用户明确取消后续 TalkBack 验收，该项保留为未核实，不再阻塞交付。此范围调整不移除自动记账使用的无障碍服务，也不影响普通点按和键盘操作。

项目：OMyMoney。包名：`app.omymoney.android`。版本：`0.1.0 (1)`。最低 API 26，目标 API 36。Room schema 10，完整 ZIP schema 8。

## 已实现范围

- 多账本、账户及分组、分类及归档排序，精确金额、统一事务分录、编辑、删除和撤销。
- 手工草稿、原始输入恢复、私有图片附件，规则识别候选、待确认队列、浮层确认与离线中文 OCR。
- 退款、报销、借贷本金与利息、信用卡还款及周期设置，多币种实际收付款、手动汇率和资产历史。
- 月年及分类预算、预算复制删除标记、统计筛选、趋势、分类、日历及年度汇总。
- 周期记账、分期、离线补执行和幂等保护，存钱计划及关联转账入金。
- CSV/XLSX/JSON 预览导入、映射、逐行错误、重复文件保护、导出回读，原子批量操作及持久化撤销历史。
- 完整 ZIP 校验、合并及覆盖恢复、覆盖前恢复快照，设备凭据隐私锁、截图限制、标准小组件和快捷入口。
- 原生 Compose Material 3 / Material You、浅色深色及系统主题、紧凑与宽屏布局。

生成式本地或云端 AI、原版账号和服务器功能不在已批准的本地范围内。OCR 模型随 APK 提供，不在运行时下载。完整功能到测试的对应见 `full-coverage.json`，差异见 `known-differences.md`；阶段 A/B 的历史报告不替代本报告。

## 原生流程核查

- 三个 API 均通过完整业务组合的 prepare、实际 force-stop、独立 verify；每个系统检查 360dp 浅色及 600dp 深色，字体均为 200%。不是只调用 Activity 重建来代替进程恢复。
- 集成样本含 14 笔已提交账单，并保留手工、识别和定期任务的未确认输入。断言现金 CNY 1042.45、银行 CNY 181.99、外币 USD 89.90、负债 CNY -60.00，预算剩余 CNY 91.73、存钱进度 CNY 50/100。
- CSV、XLSX、JSON 导出各读回 14 条；重复导入被识别；批量编辑及撤销、ZIP 覆盖后业务 JSON 一致。隐私偏好不会因业务备份恢复而关闭。组合数据通过正式仓库接口生成，不冒充逐个表单的手工输入证据。
- 三个系统的跨功能测试均在紧凑、宽屏大字体和短横屏通过：计划历史、存钱关联转账、识别历史删除后均能看到并使用撤销；外部账本入口不会丢掉被中断的计划或入金表单。关键原生截图已逐张抽查。
- 三个系统均使用真实临时系统 PIN 验证启用、错误 PIN、取消、后台重锁、快捷入口和 OCR 锁定、重建、锁屏返回及关闭隐私锁。API 26 用系统凭据页面，API 34/36 用平台认证路径。测试 PIN 已清除；不是生物识别硬件覆盖声明。
- 原生 Tab、Shift-Tab、Enter 事件完成金额输入及保存；普通文本角色在当前固定和动态浅深色调色板通过对比度断言。不推断所有壁纸、组件状态或外接实体键盘均已覆盖。
- TalkBack 的真实流程未核实，按用户要求停止；没有将一次失败的测试节点查找包装成通过。

## 发现与修复

独立代码及跨功能 UX 审查的已接受重要问题均完成失败复现和修复：历史批量快照引用保护、单行金额溢出的逐行错误、子页面删除撤销反馈、外部入口保留未提交表单。

API 26 实测另外发现并修复两个兼容缺陷：阻塞文件提供方管道不能及时取消，以及旧系统凭据结果在 onStart 前返回时被误判失败。分别使用真实管道取消、原生生命周期和真实系统 PIN 回归验证。没有为通过测试而放宽账务校验或绕过认证。

部分早期失败来自测试夹具或模拟器本身，例如旧系统截图尺寸超过物理显示、旧启动器的强制横屏布局崩溃、系统文档页的按键注入权限，以及凭据字段选择过早。这些诊断与最后成功结果分开保留，不算应用已通过的证据。

## 性能边界

1000 行、61,945 字节 CSV 的精确导入、重复识别及完整备份检查通过。最终 API 34 模拟器预览 5,108ms、提交 5,733ms；API 36 为 4,683ms、5,115ms。原始计时输出保留在数据层测试日志中。这只是开发机上的 1000 行检查，不是物理手机性能承诺，也不是 10,000 行规模的性能验收。
