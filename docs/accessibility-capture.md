# 本地无障碍采集

## 权限与隐私

- 初始识别总开关关闭，七个应用均未选中。启用先显示用途与保存说明，再由用户在 Android 系统设置中单独授权。代码不自我授权，不执行节点点击，不请求截图或手势。0.2 起独立诊断开关可记录所选应用的各类事件和可读页面，并在显式配对后上传；APK 更新也使用联网权限，见 diagnostics-updates.md。
- 服务以 `BIND_ACCESSIBILITY_SERVICE` 保护，声明 `isAccessibilityTool=false`，只接收已选择应用的窗口/内容事件；停用、暂停或未选择应用时使用不匹配任何支持应用的包名过滤。
- 每轮读取前后重新核对持久设置、系统实际授权、连接代次、事件时间和解锁状态。设置页在恢复前台及绑定状态变化时重新读取实际授权；系统已授权与服务已连接分开显示。
- 只读取当前根节点，不保留 AccessibilityEvent/AccessibilityNodeInfo。密码、可编辑字段、系统敏感节点、不可见节点及异包子树在读取文本和子节点之前跳过。微信支付密码窗口不采集。
- 节点、深度、子节点、字段、总字符和读取时间均有界。截断快照不能进入规则识别；主线程不执行节点 IPC。原始页面快照不落盘、不记日志；仅将规则字段依据经队列隐私清洗后保存在本机。

## 调度与结果

- 单工作线程加容量为一的事件通道；新事件立即递增代次，旧的阻塞 IPC 即使之后返回也不能出队。内容事件在 450 ms 后取新根，支付宝使用已有 160/450 ms 两轮规则契约。
- 连接前/超过五秒的事件失效。重连不主动读取上次根节点，必须等待新事件。近五秒相同页面指纹合并，最多保留 32 个散列，不缓存原文。
- 0.2.3 起，确认付款成功且金额明确的无障碍识别在同一数据库事务内保存识别记录和账单。缺少页面时间时使用明确标注为估算的识别时间；扣款账户未识别时照常入账，但不虚构现金等资产分录。未知页面不入队；未付款、金额冲突和身份歧义保留待核对问题。队列容量/存储失败显示错误状态，不把识别计数当作保存计数。
- 暂停、未授权、锁屏和服务未绑定不影响手工记账。服务断开不删除已有队列。

## 验证范围

`AccessibilityCaptureTest` 覆盖受保护子树、读取上限、未授权/暂停/未知包、重复事件、重连旧事件、读取中撤销、窗口变化和未付款样本。额外阻塞 IPC 测试先观察到旧窗口错误入队两次，再通过立即递增代次修复。

`AutomationSettingsTest` 覆盖明确同意/取消、暂停、应用选择、无授权状态、损坏设置关闭采集，以及仍能手工保存。API 34 专用模拟器检查 360 dp 浅色及 600 dp 深色、200% 字体；正文可滚动且对话框操作可达。

`AccessibilityPermissionTest` 只在显式 `permissionDeviceTest=true` 时执行，用 Android 原生设置页面授权、撤销、再次授权及撤销，断言实际授权与服务连接同步；普通回归跳过此改变系统授权的测试。原生适配器读取实际设置页面也在此验证。

这些检查不是七个支付应用的实机兼容性证据。第三方应用版本差异、厂商后台保活、真实交易页面、API 26/36 与实体设备仍须独立实测，不能从合成节点样本外推。

## 0.2.2 支付页面语义修复

2026-10-13 收到的支付宝真实页面已经完整采集到 27 个节点，失败点是状态标题在描述字段中合并为 `支付成功￥0.01`，而旧规则只接受完全相等的 `支付成功`。脱敏回归保留节点类型、层级和索引，仅将收款方替换为测试名称；没有把采集服务未连接与规则不匹配混为同一个故障。

- 七类应用共用文本与描述别名、全角/空白规范化、明确状态前缀及状态与金额合并解析；不把任意包含成功字样的文本视为付款成功。
- 字段支持同父节点的分片标签、内联值、嵌套空容器和分离货币符号。冲突金额、独立多值和越界容器仍保留缺失/歧义，不任取第一个值。
- 商品/备注子树即使因多值而无法提取，也不能成为付款状态证据。失败、待扣款、退款、先用后付等优先于成功，文本和描述中的风险提示均参与判断。
- 余额、订单原价、优惠和手续费不冒充实付金额；收入、还款、充值等原有方向保留。缺失时间和账户仍需人工确认，不使用抓取时间冒充交易时间，不自动写账。

`PaymentSemanticsRegressionTest` 与 `PageFieldsRegressionTest` 覆盖真实脱敏样本、七类规则目录和上述变体/反例。`AlipayCaptureFlowTest` 在 Android 中回放该样本，检查事件合并、0.01 元待确认草稿、未确认时间与账户，并通过真实编辑界面手动选择后保存。它不等同于已经在用户手机上完成新版本真实支付宝支付复测。

## 0.2.3 自动入账

- 同一支付页面的重新绘制复用持久记录，不再以整棵节点树变化创建第二笔账单。明确的付款入口、扫码或付款码页面结束上一支付过程；不同订单、金额、已知交易时间或交易对方不强行合并。
- 成功页与详情页的关联同时检查规则对应关系、页面时间和当前支付过程。多笔相似付款无法区分时不猜测身份，也不自动创建额外账单；待核对原因跨进程保存，不会因时间窗口过期而转为自动保存。
- 渠道、交易对方和资金账户分别保留。资金账户仅在唯一、明确的名称或别名依据下匹配，银行卡还须尾号与名称一致。未识别账户可以之后补选，也可以撤销选择；账务分录随修改原子更新。
- 后到的时间、对方、账户或手续费只补充尚未人工修改的账单。不会覆盖用户修改，也不会重新建立已删除账单。
- 提示只在事务完成后显示，包含方向、金额、渠道和交易对方。点击直接编辑已保存账单；浮层不抢焦点，按系统推荐时长关闭，锁屏和隐私锁立即隐藏。
- 屏幕事件、无障碍事件和应用恢复前台均刷新实际解锁状态；屏幕亮起后的短暂锁定状态有有界重查。读取上下文不再重复写默认偏好，避免无意义的无障碍配置重设。

模拟器回放和脱敏样本不等于用户实体手机上的新版本支付宝实付验证。旧待核对记录不因升级自动补记或删除。

## Android 依据

- [AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)：节点敏感/密码属性与节点生命周期。
- [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)：系统绑定、窗口事件与当前根节点。
- [AccessibilityServiceInfo](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo)：包过滤、报告 ID 和真实用途声明。
